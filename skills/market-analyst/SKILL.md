# Рыночный пульс: общая картина через QuantumStock MCP

Сервер: `QSmcp` (облако QuantumCP на amvera). Двухуровневая архитектура: `fast_*` — из Redis (<5мс, TTL 5м), тяжёлая аналитика — COMPUTE с фоновыми задачами. Время везде **UTC**.

## Общие правила (читать первым)

- **Сначала дешёвое**: `get_time_check` (мгновенно, проверка живости + текущее UTC) → `fast_*` → тяжёлое.
- **Облако деградирует окнами**: тяжёлые вызовы висят до ~50с и падают в таймаут, до 30% отказов. Один таймаут — НЕ ошибка сервера: пропусти эндпоинт, попробуй фолбэк или повтори позже. Не делать много тяжёлых вызовов параллельно — они замедляют друг друга.
- **202 — не ошибка**: тяжёлая аналитика при Redis MISS возвращает `job_id` + расчёт идёт в фоне. Проверь `get_job_status(job_id)` через 30–60с или повтори тот же вызов через минуту (HIT отдаст данные).
- **401** — истёк JWT или не задана env-переменная `QS_ACCESS_TOKEN` (настройка — в README плагина). Попроси пользователя обновить токен и начать новую задачу.
- Реестр возможностей сервера: `get_skills_registry` (начать здесь) и `get_skill_detail(skill_id)`.

## Воркфлоу «брифинг по рынку»

Порядок шагов; шаги независимы — что-то упало, идём дальше.

1. **Время/живость**: `get_time_check` → зафиксировать UTC-время брифинга.
2. **Снимок рынка**: `fast_snapshot` (37 инструментов, Fear & Greed, intermarket, sector rotation — из Redis, TTL 5м). Если висит/таймаут → фолбэк `get_enhanced_market_snapshot` (то же, но из COMPUTE, медленнее).
3. **Сигналы**: `fast_signals` — multi-signal confluence по всем тикерам (7 источников: HMM × SMC × ML × Tech × GEX × VWAP; обновляется шедулером каждые 45м). Фильтры: `verdict` (BUY/SELL/HOLD), `min_confluence` (0–1), `limit`. Для сигнала по одному тикеру есть тяжёлый `analytics_signals(ticker)`.
4. **Беты/корреляции**: `fast_beta_ranking` (беты к SPY) или `fast_correlation_map` (матрица + топ-пары |corr|>0.3).
5. **Экономкалендарь**: `fast_economic_calendar` — что сегодня/на неделе; `high_only=true` только важное, `country` для фильтра.
6. **Новости**: `get_global_market_news` (глобальный брифинг Markdown: Redis livesquawk → файловый кэш blogspot). Часто медленный — ставить последним; при таймауте → `get_rss_sources` + `fast_news(source)` по 1–2 ключевым источникам.
7. **Режим рынка (опционально)**: `get_hmm_regime(ticker="SPY")` — HMM-детекция режима (бычий/медвежий/боковой из n_states=5).

## Формат ответа

Краткий брифинг: дата-время UTC → режим рынка (HMM) → Fear & Greed → межрыночные связки (акции/бонды/доллар/золото/нефть/VIX) → ротация секторов → топ-сигналы confluence (тикер, вердикт, score, сколько источников согласно) → беты-выбросы → что в календаре → 3–5 главных новостей. Всё числовое — из ответов инструментов, ничего не додумывать. Если какой-то блок не получен из-за таймаута — честно пометить «данные недоступны (облако деградирует)», не заменять памятью.
