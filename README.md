# QuantumStocks — плагин аналитики рынка для ZCode

Плагин подключает [ZCode](https://zcode.ai) к HTTP MCP-серверу **QuantumStock** (облако QuantumCP) и добавляет три навыка аналитики: рыночный брифинг, глубокий разбор тикера и макро-контекст. 46 инструментов: рыночные снимки и confluence-сигналы, фундаментал и скоринг компаний, технический анализ, Smart Money Concepts, HMM-детекция режимов, ML-прогнозы (ансамбль из 5 LSTM + HMM consensus), опционы и Gamma Exposure, данные FRED, RSS-новости.

> ⚠️ Плагин — обёртка над **приватным API** (`mcp-antonbustrov.waw0.amvera.tech`). Без валидного JWT все вызовы инструментов возвращают 401. Токен выдаёт владелец сервера (см. [Настройка токена](#настройка-токена)).

## Как это устроено

Сервер QuantumStock работает в двух уровнях:

1. **FAST (Redis)** — инструменты с префиксом `fast_*` отвечают за миллисекунды (кэш TTL 5 минут, обновляется шедулером).
2. **COMPUTE (аналитика)** — тяжёлые расчёты (GARCH, GEX, корреляции, ML). Если результат уже в кэше — ответ мгновенный; если нет — возвращается `202` с `job_id`, расчёт идёт в фоне, результат забирается через 30–60 секунд.

Плагин регистрирует MCP-сервер как `QSmcp` — инструменты появляются в сессии ZCode автоматически при включённом плагине. Навыки (skills) задают порядок работы: от дешёвых вызовов к тяжёлым, с фолбэками на деградации облака.

## Требования

- ZCode (Desktop) с поддержкой плагинов и MCP
- JWT-токен доступа к API (см. ниже)
- macOS / Linux / Windows — плагин не содержит исполняемого кода, только конфигурацию MCP и skills

## Установка

### Шаг 0. Получите токен

Токен — это JWT (`Authorization: Bearer <jwt>`), который выдаёт владелец сервера QuantumCP. Без него плагин установится, но все инструменты будут отвечать 401.

### Вариант A — через локальный маркетплейс (рекомендуемый, гарантированно работает)

```bash
git clone https://github.com/antonBy77/quantumstocks.git
cd quantumstocks
# задайте токен (см. следующий раздел) — и перезапустите ZCode
```

Затем в ZCode:

1. Откройте **Plugin Marketplace → Add → Add Plugin Marketplace**.
2. Вставьте **абсолютный путь к каталогу**, куда склонировали репозиторий (например `/home/user/src/quantumstocks`). Вставляется именно корень репозитория: маркет-каталог лежит в `.claude-plugin/marketplace.json`.
3. Откройте **Personal → quantumstocks → QuantumStocks → Install**.
4. Управление установленным плагином — в **Settings → Plugins**.

### Вариант B — из GitHub напрямую

Если ваша версия ZCode умеет добавлять маркетплейсы по git-URL, укажите `https://github.com/antonBy77/quantumstocks` в **Add Plugin Marketplace** и далее установите плагин как в варианте A. Если хост требует локальный каталог — используйте вариант A.

### Обновление

```bash
cd quantumstocks && git pull
```

В ZCode: **Plugin Marketplace → Marketplace Sources (шестерёнка) → Refresh** у этого рынка → **Personal → QuantumStocks → Update**. Правки исходников не подхватываются горячей перезагрузкой — нужен и refresh рынка, и Update плагина.

## Настройка токена

`.mcp.json` плагина берёт токен из переменной окружения:

```json
"Authorization": "Bearer ${QS_ACCESS_TOKEN}"
```

**Основной способ — env-переменная** (токен не хранится в файлах репозитория):

```bash
# bash/zsh — добавить в ~/.bashrc или ~/.zshrc
export QS_ACCESS_TOKEN="eyJhbGciOi... ваш JWT"
```

После `export` **перезапустите ZCode** — процесс должен увидеть переменную при старте.

**Запасной способ** — вписать токен прямо в `.mcp.json` клона (до установки через вариант A):

```json
"Authorization": "Bearer eyJhbGciOi... ваш JWT"
```

Никогда не коммитьте изменённый файл: токен в публичной истории репозитория скомпрометирован навсегда (git помнит всё).

Проверка токена без ZCode:

```bash
curl -s -X POST "https://mcp-antonbustrov.waw0.amvera.tech/mcp" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer $QS_ACCESS_TOKEN" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_time_check","arguments":{}}}'
```

Валидный токен вернёт JSON с `system_time`; просроченный — `401 Not authenticated`.

> Важно: авторизация идёт **только** через стандартный заголовок `Authorization: Bearer`. Кастомные заголовки вида `access_token`/`token_type` сервер игнорирует при вызове инструментов.

## Навыки и примеры запросов

После установки создайте новую задачу и выберите навык плагина в композере (или просто сформулируйте запрос в духе описаний — ZCode подберёт сам).

| Навык | Когда срабатывать | Пример запроса |
|---|---|---|
| `market-analyst` | «что сейчас на рынке», брифинг, настроения, сигналы, беты, календарь | «Дай рыночный брифинг: снимок, сигналы, что в экономкалендаре» |
| `ticker-analyst` | «проанализируй тикер», «стоит ли заходить в X», прогноз, вердикт | «Проанализируй NVDA: фундаментал, техника, HMM-режим, ML-прогноз и confluence-вердикт» |
| `macro-fred` | макро: ставки, CPI, ВВП, кривая, календарь, FedOdds | «Что с кривой 10Y-2Y и вероятностями ФРС до конца года?» |

Ожидаемый результат триала `ticker-analyst`: агент вызывает инструменты `QSmcp` (fundamentals → теханализ → SMC → HMM → ML → опционы → риск → confluence) и выдаёт вердикт с реальными числами, метриками качества прогноза и уровнями. Прогноз ML всегда сопровождается метриками ошибки — это требование навыка.

## Решение проблем

| Симптом | Причина и что делать |
|---|---|
| `401 Not authenticated` | Токен не задан / истёк. Проверьте `QS_ACCESS_TOKEN` и перезапустите ZCode; проверьте curl-командой выше. |
| Вызов висит ~50с и умирает | Деградация облака (бывает окнами). Навыки это учитывают: быстрый слой `fast_*` работает стабильно; тяжёлый вызов можно повторить позже. |
| Ответ вида `202` + `job_id` | Это **не ошибка**: расчёт идёт в фоне. Навык сам проверит `get_job_status(job_id)` через 30–60с или повторит вызов через минуту. |
| Пустые данные по тикеру | Тикер не поддерживается данным эндпоинтом (например, GEX — только акции/ETF, не фьючерсы) — попробуйте соседний инструмент навыка. |
| Плагин установлен, инструментов нет | Проверьте, что плагин включён в Settings → Plugins, и начните **новую** задачу — старая могла закешировать старый каталог возможностей. |

## Структура репозитория

```
quantumstocks/
├── .zcode-plugin/plugin.json   # манифест плагина (имя, версия, компоненты)

├── skills/
│   ├── market-analyst/SKILL.md # рыночный брифинг
│   ├── ticker-analyst/SKILL.md # глубокий разбор тикера
│   └── macro-fred/SKILL.md     # макро-контекст FRED
├── README.md
└── LICENSE
```

## Разработка

- Правьте `skills/*/SKILL.md` и манифест; при каждом изменении инкрементируйте `version` в `.zcode-plugin/plugin.json` и в `.claude-plugin/marketplace.json` (должны совпадать).
- Для локальных экспериментов можно добавить свой дев-маркет: в ZCode добавьте каталог репозитория как маркетплейс (как в варианте A).
- Полный список инструментов сервера — вызовите инструмент `get_skills_registry`, детализацию — `get_skill_detail(skill_id=...)`.
- Формат плагина совместим с экосистемой Claude-плагинов (`.claude-plugin/marketplace.json`); работа вне ZCode не тестировалась.
